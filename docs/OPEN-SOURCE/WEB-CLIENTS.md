# Web client MCP adaptation survey (2026-11)

> Scope: research only. No code, config, commit, push, or deploy changes.
> Grab date for every URL below: **2026-11-23** unless noted. "未验证" means we
> found no first-party source or no reproducible report; do not treat it as fact.
> Repo baseline: Gemini web custom apps are the **only actually tested** client.
> Gateway today: OAuth 2.1 DCR + PKCE S256, Streamable HTTP at `/mcp`,
> stateless, three tools (`search` / `execute_read` / `execute`), MCP SDK
> 2025-11-25 legacy. See [CLIENTS.md](../CLIENTS.md) and
> [GEMINI-OFFICIAL-DOCS.md](../GEMINI-OFFICIAL-DOCS.md).

## 0. Bottom line

- **Streamable HTTP + OAuth 2.1 DCR + PKCE S256 is the right common baseline.**
  Every first-party web-client doc we found accepts it or a superset of it.
- **The blockers are account/policy and schema size, not transport.** ChatGPT
  full MCP is Business/Enterprise/Edu only; Gemini custom apps are US/personal/
  18+/English only; Claude has per-plan and admin gates but the widest support.
- **Our three-tool surface is unusually small, which helps everywhere.** The
  risks are the opposite: ChatGPT requires `readOnlyHint` to avoid write
  confirmations and may reject tool text that "suggests arbitrary code
  execution" — our `execute(code)` name/description is a real risk there.
- **ChatGPT wants `structuredContent` + JSON text and output schemas for
  search/fetch-style tools**; Gemini explicitly does not support
  `structuredContent`. That is a genuine client-specific adapter need.

## 2. Priority

### 2.1 Must adapt for open-source first launch

1. **Gemini web custom apps (already done).** Keep the current guarantees:
   Stable tool list, no mid-session schema change, `sanitizeTool` before
   registration, `server__tool` naming, text-JSON results, 405 on GET stream,
   non-rotating refresh tokens, DCR + S256.
2. **MCP Inspector / local smoke** as the reproducibility target for any
   client-compat claim (already in [CLIENTS.md](../CLIENTS.md)).
3. **Baseline OAuth hygiene that all clients check**: 401 with
   `WWW-Authenticate: Bearer resource_metadata="…"`, AS metadata with
   `registration_endpoint`, `code_challenge_methods_supported:["S256"]`,
   `grant_types_supported` incl. `refresh_token`, `response_types_supported`
   incl. `code`, `offline_access` in `scopes_supported`, exact `resource`
   matching, <10s on authorize/register/token endpoints. Sources:
   [Google OAuth guide](https://developers.google.com/connected-apps/mcp/oauth),
   [Claude auth](https://claude.com/docs/connectors/building/authentication.md),
   [OpenAI plugin auth](https://developers.openai.com/plugins/build/auth).

### 2.2 Needs a client-specific adapter (do not scatter `if (client)` in core)

| Adapter axis | Client-specific behavior | Why |
|---|---|---|
| **Tool annotations / safety labels** | Gemini needs `openWorldHint`+`destructiveHint` for confirmation gates; ChatGPT treats missing `readOnlyHint` as write (confirmation); Claude **requires** both hints declared. | Same JSON field set, different defaults/consequences. Add explicit annotations centrally, not per tool. |
| **Result encoding** | Gemini: text JSON **only** (no `structuredContent`). ChatGPT: `structuredContent` **and** same JSON in text for search/fetch compatibility; citations need non-empty `url`. Claude: text/image results fine, ~150k char cap. | Adapter layer can add `structuredContent` only for client profiles that accept it. |
| **Tool naming / schema validation** | Gemini splits on first `_` → our `__`; Google wants verb_noun and flat schemas (we sanitize). ChatGPT security review may reject code-execution-flavored names/descriptions. | Keep one canonical name; expose a friendlier display name/description profile for ChatGPT if we pursue it. |
| **Auth transport** | DCR works for Google/ChatGPT/Claude/Grok(?). Claude beta and Copilot Studio support static header credentials; ChatGPT explicitly does **not**; Gemini Enterprise needs client id/secret. | If we add a static-header mode, it must be a separate endpoint/profile, not a change to the DCR flow. |
| **Tool surface size** | ChatGPT has undocumented schema-token/volume caps; Gemini flags dozens of tools; VS Code 128 tools/request. | Our 3 tools are safe; never expand the default surface without per-client profiles. |
| **Session/protocol version** | Gemini pinned to 2025-11-25 legacy; other clients may accept 2026-07-28 stateless. | Keep 2025-11-25 as default; version paths (`/mcp/v1`) when upgrading, as [PLAN-2026-11-23](../PLAN-2026-11-23.md) already decides. |

### 2.3 Not supported / do not promise

- **SSE-only servers/clients**: Google rejects 2024-11-05 SSE; Copilot Studio
  dropped SSE after Aug 2025. Our server is Streamable HTTP only — consistent.
- **ChatGPT consumer plans (Free/Go/Plus) with full read/write MCP**:
  first-party help gives full MCP only to Business/Enterprise/Edu; Pro is
  read/fetch only. Do not advertise as working for personal accounts.
- **ChatGPT mobile custom MCP servers**: web only, per OpenAI help center.
- **Grok OAuth+DCR**: broken in one reproducible third-party report; mark
  未验证/broken until we re-test.
- **Perplexity remote MCP**: "coming soon" in official help; do not promise.
- **Consumer Copilot web BYO MCP**: no first-party evidence; 未验证.
- **Gemini work/school accounts and non-US personal accounts**: custom apps
  are US/18+/personal/English-only on the consumer surface; Enterprise is a
  different, admin-driven flow requiring client id/secret.

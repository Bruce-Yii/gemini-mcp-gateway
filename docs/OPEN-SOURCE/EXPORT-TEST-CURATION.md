# OSS export: test curation

`npm test` in the clean OSS export must be green without private eval fixtures.
This document records which tests are public-safe, which are gated behind
fixtures, and why. It is part of the allowlisted export (`docs/OPEN-SOURCE/`).

## Verification (clean export / staging)

```
cd work/oss-export-staging   # generated by: node scripts/export-oss.mjs --out work/oss-export-staging --write
npm ci
npm test
```

Result at the time of writing:

```
ℹ tests 761
ℹ pass 684
ℹ fail 0
ℹ skipped 77
```

Skips are **explicit**: `node:test` prints each skipped test with a `# <reason>`
suffix. Nothing is silently reported as passing.

## Private assets excluded from the export

These paths are in `scripts/export-oss.mjs`'s `DENYLIST` (via `explore`, `data`,
or the owner-only workflow rules). They are evaluation/harness assets, not
runtime dependencies of the gateway:

| Private path | What it is | Tests that need it |
| --- | --- | --- |
| `explore/trace.mjs` | Explorer anomaly detector / worker-pool implementation with eval-only behaviour | `detector`, `harness-parallel`, `merge-collector-contract` |
| `explore/golden-mcpmark.mjs` (+ local MCPMark clone) | Authoritative MCPMark task loader / verifier classifier | `golden-mcpmark` |
| `explore/baselines/l1-smoke.json` | Frozen G6 L1 baseline snapshot | `l1-baseline`, `l1-smoke` |
| `explore/select-smoke.mjs` | Deterministic 50-task smoke selector | `l1-smoke` |
| `explore/tasks-g6.json`, `explore/tasks-smoke.json` | Private task sets used to pin selection/baseline numbers | `l1-smoke` |
| `explore/tasks-v2.json` | Offline search-recall query set | `search-rework` (recall guard only) |
| `explore/figma-tasks.json`, `data/tool-snapshots/figma.json`, `data/tool-dataset.json` | Figma task/snapshot + production tool dataset | `task-coverage`, `search-cjk`, `search-rework` (recall guard) |
| `.github/workflows/l1-smoke.yml` | Owner-only scheduled real-mode smoke workflow | `l1-smoke` (static workflow assertions) |

No real credentials, captures, or personal paths are involved: the gates are
plain `existsSync()` checks on paths that never exist in the export.

## Curation policy

1. **Keep public tests running.** Pure logic tests (catalog term expansion and
   ranking with synthetic entries, L1 metric/compare/report/arg helpers, all
   other `tests/*.test.js`) are unchanged and still run in the export.
2. **Gate only the fixture-dependent cases.** A test gets `{ skip: reason }`
   when its fixture is absent. The same test runs unmodified in the private
   repo when the fixture exists — no behaviour change there.
3. **Dynamic import for private modules.** Files that statically imported
   `explore/*.mjs` or imported modules that read private files at load time now
   use a conditional `await import(...)`. Previously the whole file failed to
   load (9 file-level failures); now each test is reported as SKIP with a reason.
4. **Never fabricate fixtures.** The export does not ship redacted or stub
   copies of eval data. A missing fixture is a skip, not a fake pass.

## Follow-up work to reduce skips

If the public project wants these areas covered, add **new, neutral fixtures**
under `tests/fixtures/` (allowlisted because `tests/` is exported), not copies
of private eval data:

- A tiny synthetic detector/worker-pool module with the same exported surface
  as `explore/trace.mjs`, plus tests against it. The existing private tests can
  stay pointed at the real implementation.
- A minimal L1 fixture: 5 synthetic tasks + a small baseline JSON with known
  metrics, and a public workflow file with equivalent assertions. This would
  let the selector/baseline/report tests run without G6 data.
- A small synthetic tool catalog (a few `server__tool` entries with CJK-ish
  descriptions) for the search-recall and CJK ranking tests.
- A hand-written Figma task set + snapshot with 2-3 tools for coverage tests.

Until those exist, the skip reasons above are the authoritative record of what
is intentionally not exercised in the public CI.

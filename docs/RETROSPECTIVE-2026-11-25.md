## 二、最值钱的一课：零偏袒 Gemini A/B 实测带来的彻底“祛魅”

2026-11-25 用同一份 8 题测试集（覆盖 GitHub + Notion + Linear 三个共同上游，由轻到重），在两个全新 Gemini 窗口进行了严格控制变量的 A/B 实测（A 组原文见受控仓 `33f3b956`，B 组见 `814d289d`）：

| 维度 | A 组（Gemini 原生直连） | B 组（Gemini Mcp Gateway） | 真实胜负 |
|---|---|---|---|
| **8 题真值完成度** | **7.5 / 8**（第 4(a) 题读不到 `capture.js` 正文直接失败） | **8 / 8 全满分**（41,278 字符、行号、10 PR 增删总和全准） | **B 组完胜** |
| **外层业务工具调用** | **52 次**（原始返回全砸进上下文） | **6 次**（约 50 次上游子调用在沙箱内消化） | **B 组碾压（-88.5%）** |
| **交互轮次与墙钟总耗时** | **5 轮** / 耗时差不多 | **5 轮** / 耗时差不多（纯工具 33.43s，含 ~7.3s 参数补查） | **打平** |
| **参数 / 工具异常报错** | **1 次异常报错**（Linear / Notion **0 参数错**） | **2 类共 7 次子调用报错**（Linear 猜错 `fields` 1 次 + Notion 缺独立 ID 6 次） | **A 组胜** |
| **上游接入范围（场外事实）** | **Vercel 不在 Gemini 白名单，连不上** | **5 大上游全通**（含 Vercel 73 tools） | **B 组胜** |

### 这场 A/B 测试彻底证伪了什么，又实锤了什么？

**被证伪的旧叙事（必须诚实放弃）：**
- **“靠省上下文 + 多步编排就能打动普通网页端用户”站不住脚**：现代大厂宿主（如 Gemini）已经把**按需加载（deferred loading）+ 单轮多工具并行调用 + 粗粒度参数过滤**做成标配。在短会话、轻度查询、网页包月场景下，直连总耗时并不比网关慢；反而因为直连暴露完整原生 Schema，模型很少猜错参数，而网关把 Schema 藏在紧凑签名后面，一旦模型偷懒盲猜就会多出 1 轮报错补查。
- **自定义 MCP 激活门槛被高估**：在 Gemini 中，自定义 MCP（无论直连还是网关）都只在首轮需要 `@` 激活，后续同会话持续挂载。

**经受住实锤考验、真正站得住脚的 4 条硬刚需：**
1. **修补宿主协议残缺（决定性刚需）**：经亲测实锤，Gemini 原生直连官方 GitHub MCP 时，只读 `type: "text"` 块而丢弃内嵌 `type: "resource"` 块，导致仓库里**任意单个文件**（哪怕 2KB 的 `package.json`）都只返回 `successfully downloaded text file (SHA: ...)`，正文一个字读不到。网关中间层解包 `resource.text` 是目前唯一解。
2. **突破宿主白名单限制**：Vercel 等未入白名单的上游，直连根本接不进 Gemini，经网关直接打通。
3. **长会话保窗 & 精确计算 & API 成本**：外层业务调用从 52 次压到 6 次（-88.5%），在 20+ 轮重度工程会话、大文件批量审计、精确统计求和以及按 Token 计费的 API / CLI Agent 场景下价值显著；且裁剪控制权在模型脚本手里（精读全文就 `return content`，筛选统计就端内算完只吐摘要）。
4. **多 AI 客户端一套上游鉴权复用**：Gemini / ChatGPT / Claude / Codex 共享同一份托管好的 OAuth/PAT 与物理隔离适配层，免去重复配置与 OAuth 互踢。

## 三、评测体系实战沉淀：亲手踩穿的 6 个“自欺欺人”大坑

这五六天在 Agent 评测体系上踩过的每一个坑，都是以后做任何 Agent 项目最值钱的防雷资产：

1. **坑 1：把“单测绿 / PR 合并 / 本地直连 200”误当成“线上验收通过”**
   - *真实案例*：PR #29 切完 Notion 网关 OAuth 后本地直连 `tools/list` 返回 200，但生产运行时 `codemode.services()` 仍是 `offline (0 tools)`——因为 `_resolveToken` 在无 `tokenEnv` 时提前 return 了（PR #31 才根治）。
   - *铁律*：任何修复只有经过**目标生产环境真实端到端实测**才能标 PASS，否则永远标“已合入待验收”。
2. **坑 2：把采集管道静默截断误判为客户端行为**
   - *真实案例*：R2 `listR2Keys` 没写 cursor 分页，静默只返回前 20 条 UUID，最初竟被误当成 Gemini 的 20 次调用上限；修分页后同窗数据瞬间从 2 条恢复到 34 条（PR #28），同时顺手暴露了 R2 REST API 1,200 req/5min 账户限流（PR #30/45 根治）。
   - *铁律*：所有采集/列表接口触顶必须显式带 `truncated: true` 与告警，绝不允许静默截断。
3. **坑 3：被动分析器对 HTTP 200 语义故障全盲**
   - *真实案例*：`normalizeMerge` 返回 `number: null, url: null`、`writeFiles` 静默 0 写入，但因为 HTTP 状态码是 200，旧分析器不喂 `responsePreview`，免费模型一条都抓不到。
   - *铁律*：被动分析必须给成功样本注入脱敏后的 `responsePreview` 与 `subCalls` 结构轮廓，否则“主动反哺被动”永远闭不上环。
4. **坑 4：主被动对照的“泛词假绿”与“硬凑 missed=0”**
   - *真实案例*：`F-mcp-drop`（客户端压缩掉线，根本没发请求到网关）靠宽泛关键词 `"MCP"` 撞上无关的 `issue-1` 被判 `covered: true`（假绿）；另一边又差点把被动日志天生不可见的“工具描述过长”硬塞给被动分析器去凑 `missed=0`。
   - *铁律*：必须区分 `passive-observable`（漏检必须反哺改采集/提示词）与 `active-only`（直接进业务 Issue/Badcase，不考核被动）；严禁 `MCP`/`error`/`api` 等泛词单命中判绿。
5. **坑 5：靠文档写规则代替代码与 CI 硬门禁**
   - *真实案例*：哪怕 `AGENTS.md` 白纸黑字写了强制小闭环，只要脚本允许跳过免费模型还正常产出 `match=likely`，agent 依然会交出无 LLM 的半成品，不盯紧就被蒙蔽。
   - *铁律*：凡是不能妥协的流程（如必须执行 LLM 分析、CLI 部署必须带 `--meta githubCommitSha`、禁止跨客户端 import），全部做成**单入口脚本 + 代码强校验 + CI 红灯拦截**。
6. **坑 6：逻辑开关式“假隔离”终将沦为一锅炖**
   - *真实案例*：最初把多客户端适配塞进 2,200 行的 `codemode.js` 里靠 `profile` 字段做 `if/else`，改一个客户端极易串伤别端。
   - *铁律*：共享底座只留部署壳、上游鉴权、沙箱运行时与客观契约；各客户端的描述、预算、编码与检索策略必须**物理分目录隔离（`src/clients/<platform>/`）+ 边界检查互禁 import**。

## 四、理性决策：及时止损与最后一轮极简收官

- **产品定位止损**：不再试图把它包装成“靠省上下文说服普通网页用户替换原生连接器”的通用大众产品；正式收敛为**高可靠个人/多客户端工程生产力底座 + 完整可复用的 Agent 评测方法论资产**。
- **工具层原则拍板**：工具调用层不对任何上游、任何客户端设额外审批或弹窗实验（放行权交给各客户端 MCP 管理界面；仅保留公网入站防盗锁 `OAUTH_APPROVE_PASSPHRASE`）。
- **最后一轮极简收官动作（不再开新大坑）**：
  1. 验收合入在途收尾 PR（#52 / #53 / #54）；
  2. 一次性清掉实测暴露的最后 3 个真毛刺：补 Linear `fields` 与 Notion 列表提取 32 位 ID 的极简提示（消灭 A/B 中 B 组 7 次参数报错）、升级 `repoGrep` 递归 Git Tree（治 `BC-021`）、补 `search` 多子查询收敛（治 `search_thrash`）；
  3. 跑最后一次全量单测 + 生产带 SHA 封版部署 + Gemini/ChatGPT 各跑 1 轮 `T0` 确认全绿，正式定格为 **v1.0 自用稳定版**；
  4. Notion 稳定观测满 72h 后清理旧 DSH 连接/旧环境变量并轮换 Linear PAT，此后将其当水电煤稳定使用，回归核心业务项目。

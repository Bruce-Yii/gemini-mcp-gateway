# 全局审视与执行计划（2026-11-23）

> 状态：**执行中**。本文取代此前口头讨论，作为当前项目的全局判断、缺口清单和并行执行方案。
> **没有日历排期**。只分依赖关系：能并行的并行，完成即进入下一项；每个工作流独立验收、由 lead 统一集成。

## 0. 一句话结论

网关的“编排 + 上下文隔离”方向成立，但当前最大风险不是功能少，而是：

1. **在线数据不可信**：capture 曾因 `waitUntil` 放在 `queueMicrotask` 里而漏采；
2. **写路径语义不统一**：sha、幂等分支、PR 编号、patch/dry-run 还没收口；
3. **Gemini 下 Code Mode 需要收敛**：外部 benchmark 显示 Gemini 家族在 Code Mode 下回退。

下一步原则：**先把观测修到可对账，再把写路径收成类型化原语，最后做 Gemini 自适应；MCP 2026 暂不迁移。**

## 2. 本轮关键证据

### 2.1 Capture 漏采（已修，待真实验证）

- 北京时间 04:58 后 R2 只有 20 个 envelope；同期 Vercel 日志有大量 `POST /mcp`。
- PR #41–#48 的 GitHub 时间线为 20:04Z–21:17Z，确实发生；capture 里只有 2 次只读 `execute_read`，没有写调用。
- 根因：`startCapture` 在 `res.end` 的 `queueMicrotask` 里才调用 `waitUntil`；Vercel 冻结实例后 sink 没跑，且没有 `capture_dropped`。
- 修复：同步路径构建 envelope + 调度 sink；每条 `/mcp` 输出 `capture_ack`/`capture_done`/`capture_skipped`；requestId 可对账；单入口防双写。
- **判据**：`A === D`（ack=done）、`V - A === S`（Vercel 请求-ack=skip）、`R + dropped === A`（R2+丢弃=ack）。

### 2.2 在线/离线对照（已报告，不可硬比）

- 在线窗口 11 条 envelope：7 条 `GET /` 404、1 条 `GET /mcp` 405、2 条 `tools/list`、2 条 `execute_read`（CandidatePage.tsx，513/724ms）。
- 离线 L1 基线：50 任务、完成率 76%、gateway 异常 21、searchHit 86.4%、toolHit 51.3%、tokens/task 15,691、p95 22,025ms。
- 在线是**请求级**，离线是**任务级**，没有共同分母；不能拿 76% 和在线 0 错误直接比较。
- 能证实：读侧字段兜底、sliceLines、canonical 未接入；不能证实：sha/commit、patch/diff、行号修复、PR 写操作。

### 2.3 外部调研（2026-11 附近）

1. **MCP 2026-07-28 全 stateless**：移除 session/initialize，新增 `server/discover`、`resultType`、MRTR、`subscriptions/listen`。  
   我们 SDK 1.32.2 只到 2025-11-25；Gemini 当前 legacy。**暂不升级**，等客户端升级再做版本分流。  
   审计：[mcp-2026-07-compat.md](ledger/mcp-2026-07-compat.md)、[官方 changelog](https://modelcontextprotocol.io/specification/2026-07-28/changelog)
2. **Code Mode 对 Gemini 未必更好**：IJCA 2026 论文显示 Code Mode 平均省 token/成本，但 Gemini 家族通过率明显回退。  
   来源：[论文](https://www.ijcaonline.org/archives/volume187/number136/benchmarking-llm-tool-orchestration-in-resource-constrained-agentic-workflows-native-mcp-function-calling-vs-code-mode/)
3. **评测正在变成控制面**：orchestration + observability + evaluation + governance 是一层。  
   来源：[Arize](https://arize.com/blog/building-smarter-ai-agents-architecture-evals-and-lessons-from-the-field/)

## 4. 策略

### 4.1 先把观测做成“可对账”

没有 requestId 对账，所有评测都是猜。要求：

- 每条 `/mcp` 请求：capture ack/done/skipped 三态；
- 每条 upstream 事件带同一个 requestId；
- 写操作返回结构化 `meta`：branch、commitSha、prNumber、issueNumber、changedFiles、durationMs、upstreamCalls；
- 在线 envelope 增加 `taskId`/`sessionId` 锚点（能关联到 L1/G6 任务时）。

### 4.2 再把写路径收成“类型化原语”

不再让 Gemini 自由写兼容代码。提供固定原语：

```text
readFileRange / canonical file
applyPatch(dryRun) / diff
ensureBranch(create_if_missing)
upsertPr / mergePr
createIssue / closeIssue
fetchAllPages / repoGrep
```

每个返回固定字段，内部处理 sha、幂等、分页、patch、预检。  
Code Mode 保留给强模型/探索；Gemini 默认走结构化原语。

### 4.3 Gemini 自适应

外部 benchmark 显示 Gemini 在 Code Mode 下回退，不能继续“脚本越自由越好”。  
方向：

- 高层原语 + 明确 guidance；
- 按任务类型选择：简单多步用结构化原语；复杂探索才用自由脚本；
- 用 L1 real 对比“结构化原语 vs 自由脚本”的完成率/toolHit/tokens，数据决定。

### 4.4 MCP 2026：观察，不迁移

- 保持 legacy 2025-11-25；
- capture 记录协议版本/clientInfo；
- 等 Gemini 或其他客户端实际发 2026-07-28 请求，再做 `server/discover` + `resultType` 分流；
- 不升 SDK、不双栈、不实现 MRTR/tasks/subscriptions。

## 5. 工作流（无排期，按依赖并行）

### W1 · 观测完整性（P0，已通过真实请求验证）

- 目标：修复后的每条 `/mcp` 都能在 R2/日志对账。
- 任务：capture ack 验证；requestId 关联 upstream；写结果 meta；在线窗口复跑。
- 验收：`A===D`、`R+dropped===A`；本次 `602f4012-...` 已验证（见 `docs/eval/capture-verification-2026-11-23.md`）。
- 依赖：无；**现在就能做**。
- 并行：可与 W3、W4 同时。

### W2 · 写路径真实回放（P0，已完成）

- 目标：受控测试仓库完成 `ensureBranch → writeFiles → createPR → merge`，并能从 capture 还原。
- 任务：建临时分支/文件；调用新原语；校验顶层 number/url/sha；清理分支；记录 capture。
- 验收：真实 GitHub 操作成功、capture 有完整 envelope、失败路径不部分写。
- 依赖：W1（capture 可对账）。
- 并行：W3、W4 可同时。

### W3 · 在线/离线锚点（P0，会话标记已验证）

- 目标：让在线请求能对齐 L1/G6 任务。
- 已实现：initialize 生成 `Mcp-Session-Id`，capture 记录 `sessionId` + `clientInfo`（见 `docs/eval/session-marker-2026-11-23.md`）；join 脚本升级待做。
- 验收：至少一条真实 Gemini 会话能映射到 smoke 任务/基线。
- 依赖：W1。
- 并行：W2、W4。

### W4 · Gemini 结构化原语（P1）

- 目标：Gemini 默认用原语，减少手写兼容/锚点错误。
- 任务：给原语补 guidance/示例；A/B 对比自由脚本与结构化原语；按数据选默认。
- 验收：L1 real 的 toolHit/完成率不降，手工兜底代码减少。
- 依赖：W2。
- 并行：W5、W6。

### W5 · MCP 2026 兼容观察（P1）

- 目标：不迁移，但能识别新客户端。
- 任务：capture 记录 `MCP-Protocol-Version`/clientInfo；probe 保留；准备最小 discover 设计。
- 验收：legacy 不受影响；现代客户端能被识别并给出清晰错误/兼容路径。
- 依赖：无。
- 并行：其他全部。

### W6 · 状态与韧性（P1）

- 目标：长流程可恢复，跨实例缓存/熔断一致。
- 任务：外部状态存储（Upstash/Postgres）；任务 checkpoint；Figma 冷却跨实例；幂等 key。
- 验收：重跑不重复建分支/PR；实例重启后任务可继续。
- 依赖：W2。

### W7 · 维护性与趋势（P2）

- 目标：`codemode.js` 拆分、host/guest helper 去重；趋势/SLO 面板。
- 任务：拆 prelude/helper；统一 canonical 逻辑；scorecard 趋势。
- 验收：代码可读性/测试保持；周报有趋势。
- 依赖：W4/W6。

## 6. 执行协议（多 agent）

1. 每个工作流拆成**自包含工单**：目标、写范围、禁止 commit、测试、报告格式。
2. 能并行的工单一次发多个 subagent；每个 agent 只写自己的文件。
3. 完成即由 lead review/diff/全量测试；不等待其他 agent 的排期。
4. 有依赖的（W2 依赖 W1）等前一项验收，不硬并行。
5. 免费模型输出只作 advisory；必须过 capture 回放 + 测试 + 人审。
6. 所有线上变更走：本地测试 → CI → deploy → healthz/workflow 验证。

## 8. 风险与决策

| 风险/决策 | 处理 |
|---|---|
| capture 修复后仍漏 | 部署后用真实请求做 A/D/R 对账；不达标不上线评测 |
| 真实写回放改坏仓库 | 只用测试分支/测试文件，结束清理；dryRun 先跑 |
| 多文件写非原子 | 先预检再写；失败给补偿清单；后续做外部事务/checkpoint |
| Figma 配额 | 默认跳过 real L1；熔断/缓存；不每日烧 |
| 免费模型弱 | advisory-only；validator；capture 回放 |
| MCP 2026 | 观察；不升级 SDK；等客户端 |
| Vercel 无状态 | 外部状态/任务 ID；不依赖进程内缓存 |

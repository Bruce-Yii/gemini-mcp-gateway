# M4 Gate 5 跨客户端实测｜MCP Gateway 执行组

你现在作为 ChatGPT 客户端，对已接入的 `gemini-mcp-gateway` 执行一轮 **M4 Gate 5 跨客户端实测（全程只读，严禁任何写操作）**。

本轮与另一个使用 Direct MCP 的 ChatGPT 窗口进行对照测试。两边必须使用相同的权威测试定义、任务范围、验收标准和统计口径。唯一变量是工具调用通道。

## 一、执行通道与安全约束

1. 所有上游工具发现和调用必须通过 MCP Gateway。
2. 允许使用：
   - `mcp__mcp_gateway__search`
   - `mcp__mcp_gateway__execute_read`
3. 必须通过 `functions.exec` 调用 Gateway 工具，并使用 Gateway Code Mode 的 `codemode.<tool>(args)` 执行上游工具。
4. 严禁直接调用 GitHub、Vercel、Linear、Notion、Figma 等上游 MCP 连接器。
5. 严禁调用 `mcp__mcp_gateway__execute`。
6. 全程只读，禁止任何文件、分支、PR、Issue、Project、Notion 页面或部署的创建和修改。
7. 如果工具不可发现、服务未挂载、鉴权失败或调用失败，如实记录，不得绕过 Gateway 补做。

### 6.1 Gateway 的实际优势

1. 多上游统一编排：一次 execute_read 内完成 GitHub、Vercel、Linear、Notion 多个服务的调用。
2. 沙箱内数据处理：41,278 字符的源码在执行环境内部完成检查，只将必要证据返回模型。
3. 统一工具规范化：fileResult 和 unwrap 能够帮助处理不同上游的返回结构。
4. 跨上游数据关联：成功将 Vercel deployment SHA、GitHub main HEAD 和部署台账关联起来，发现版本差异。
